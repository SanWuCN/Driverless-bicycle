# 项目状态与路线图

更新时间：2026-10-06。

## 已完成并在实车上观察

- macOS + VS Code + CMake + Arm GCC 编译链路。
- ST-Link 四线 SWD 连接和固件烧录。
- UART7 115200 8N1 在线遥测与 CSV 记录。
- 上电后后轮默认零指令，不再无命令匀速转动。
- 扶正后自动启动：±3°、角速度 ≤1°/s、连续 2 秒。
- 动态零点估计已应用于控制，学习轮速门槛 15 tps，范围 ±1.5°。
- 实车观察：动量轮平均速度接近 0、能在零附近正负交替、零点不持续单向漂移。
- Flash 双扇区持久化写入和周期保存；已观察到序号 1、2 的成功保存，无错误标志。

## 已实现但仍需受控验证

- 断电/复位后是否正确读取最新持久化零点。代码已实现启动扫描和回退，但尚未进行一次专门的受控复位验证。
- UART7 诊断固件与回环脚本在当前最终接线上的复测。
- Keil 工程已加入 `balance_monitor.c`、`uart7_bridge.c`、`zero_persistence.c`，并将固件 Flash 上限改为 1792 KiB；仍需在 Windows/ArmClang 环境实际编译验证。

## 最高优先级待办

1. 完整安全状态机：BOOT、WAIT_UPRIGHT、ARMED、FAULT、ESTOP 等明确状态。
2. 运行中 IMU 数据超时、非法数值和帧计数停滞后立即撤销控制。
3. ODrive CAN heartbeat、encoder estimate 超时和轴错误处理。
4. 动量轮速度、加速度、加加速度和电流的执行器级硬限幅。
5. 让 ODrive watchdog 在 MCU 通信中断时自动退出闭环或归零。
6. 实体急停、电机动力隔离和故障复位流程。

## PID 调参阶段

必须按顺序推进：

1. 固定车架、车轮悬空，验证所有方向和限幅。
2. 角速度环。
3. 角度环。
4. 动量轮速度回正环。
5. PID 固定后再验证动态零点在不同胎压和地面下的表现。

每个阶段记录同样的阶跃/扰动、UART7 CSV、限幅触发、最大轮速、最大加速度和结构振动，不同时盲调三个环。

## 已知技术债务

- 部分旧源码为 GB18030/GBK 编码，且包含混合换行。
- `bike.ioc` 未完整表达后来手工加入的 UART7、I2C2、TIM2 配置。
- 历史代码变量名和注释中仍有 PWM/速度/加速度概念混用，后续应重构为带单位的命名。
- UART7 当前为阻塞式逐字节发送；20 Hz 下可工作，但未来高带宽遥测应改 DMA/环形缓冲。
- CAN 过滤器当前全通，安全版应只接受需要的节点和消息。
- Axis 0 命令/查询 500 Hz 可能需要结合 CAN 总线负载和 ODrive 实际处理能力优化。
- 加速度遥测来自速度命令差分，不是独立加速度传感器或严格限幅后的执行值。
- ODrive 厂家文本中的 120 A 是配置值，不是当前机构验证过的安全值。
