## 已实现的调参基础设施

- 角速度环已改为与 2 ms 周期无关的标准时间形式：积分为 `error * dt`，微分为 `delta(error) / dt`；加入积分限幅和输出饱和条件抗饱和。为保持现有 D 作用等效，编译默认 `RATE_KD` 从旧离散写法 `-2` 换算为标准写法 `-0.004`，`RATE_KP=-20`、`RATE_KI=0` 不变；该版本已烧录。
- 已加入细网格批量扫参工具和整批统一分析工具。计划先对 `RATE_KP=-18.0 ... -22.0` 以 `0.1` 间隔、每组 30 秒、重复 2 次采集；候选顺序使用固定种子打乱，每 5 组插入 `-20` 基准以测量时间漂移。整批结束前不逐组改变策略。
- 分析不使用拍脑袋的单一加权分数：先剔除故障/饱和组，再比较横滚误差、角速度误差、轮速和加速度四目标 Pareto 前沿。静态前沿候选之后再进入人工推车扰动试验。
- 当前已烧录固件使用标准时间形式 `RATE_KD=-0.004`，与旧离散写法 `-2` 的 D 作用等效。

## PID 调参阶段

必须按顺序推进：

1. 固定车架、车轮悬空，验证所有方向和限幅。
2. 角速度环。
3. 角度环。
4. 动量轮速度回正环。
5. PID 固定后再验证动态零点在不同胎压和地面下的表现。

每个阶段记录同样的阶跃/扰动、UART7 CSV、限幅触发、最大轮速、最大加速度和结构振动，不同时盲调三个环。

### 2026-10-06 粗调结果

- 角速度环采用标准时间尺度参数 `RATE_KP=-20、RATE_KI=0、RATE_KD=-0.004`；其中 `-0.004` 与旧 500 Hz 离散写法 `-2` 等效。
- 角度环比较了 `ANGLE_KP=-3/-4/-5/-6/-7`。`-7` 虽将静态横滚误差 RMS 降至约 `0.040°`，但角速度误差 RMS 和加速度 RMS 分别增至约 `0.467°/s`、`9.36 tps²`；粗调保留折中值 `ANGLE_KP=-5`。
- 角度阻尼比较了 `ANGLE_KD=-0.5/-1.0/-1.5/-2.0/-2.5`。`-2.0/-2.5` 明显过度；`-1.0` 控制量最低，`-1.5` 横滚 RMS 更低且无饱和。粗调保留 `ANGLE_KD=-1.5`，精调和扰动试验重点复核 `-1.0 ... -1.5`。
- 轮速回正比较了 `WHEEL_KP=0.02/0.04/0.06/0.08/0.10`；`0.06` 是该批横滚、角速度误差、轮速和加速度四目标中唯一的 Pareto 非劣点。90 秒复核中轮速持续正负穿零，无速度/加速度饱和、ODrive 超时或故障。
- 当前已验证的粗调参数为 `RATE=(-20,0,-0.004)`、`ANGLE=(-5,0,-1.5)`、`WHEEL=(0.06,0)`。恢复固件已将 `WHEEL_KP=0.06` 设为编译默认值，避免复位后回到未经本轮验证的 `0.04`。
- 2026-10-06 左向人工扰动中出现两次失稳；第二次轮速由约 `+39 tps` 反向至 `-41 tps`，速度命令在 `-50 tps` 限幅停留约 5 s，期间无 CAN/ODrive 故障。曾根据方程符号推导翻转轮速慢环方向并加入大扰动让位，但烧录后实车立即出现大幅周期振荡；这证明该符号推导与实物的 IMU/电机/反作用方向定义不符。该尝试已全部撤回，恢复版回到原轮速慢环方向，且未保留让位逻辑。后续扰动问题必须从执行器速度余量、加速度限幅和饱和恢复策略分析，不再改变已经实车验证的环路极性。
- 80 tps² 扰动试验中，第一次轻推在约 `0.48°` 峰值后自行恢复；第二次则在角度环要求过大横滚角速度后进入 `±80 tps²`、`±50 tps` 和 `±30 A` 交替饱和，最终需要人工拉回。为抑制大误差下的 Bang-Bang 过冲，角度环输出的目标横滚角速度已增加 `±5°/s` 限幅，并增加 `RATE_TARGET_SAT` 遥测标志。新固件已烧录；10 秒静态验证中目标角速度、速度和加速度饱和次数均为 0，相对动态零点的横滚误差 RMS 约 `0.160°`，角速度 RMS 约 `0.257°/s`。

## 已知技术债务

- 部分旧源码为 GB18030/GBK 编码，且包含混合换行。
- `bike.ioc` 未完整表达后来手工加入的 UART7、I2C2、TIM2 配置。
- 修改时钟相关头文件或更换构建系统时，必须确认所有编译单元的 `HSE_VALUE` 均为 12000000，不能依赖 STM32F4 默认的 25000000。
- 历史代码变量名和注释中仍有 PWM/速度/加速度概念混用，后续应重构为带单位的命名。
- UART7 当前为阻塞式逐字节发送；20 Hz 下可工作，但未来高带宽遥测应改 DMA/环形缓冲。
- CAN 过滤器当前全通，安全版应只接受需要的节点和消息。
- Axis 0 命令/查询 500 Hz 可能需要结合 CAN 总线负载和 ODrive 实际处理能力优化。
- 加速度遥测来自速度命令差分，不是独立加速度传感器或严格限幅后的执行值。
- ODrive 厂家文本中的 120 A 是配置值，不是当前机构验证过的安全值。
- 2026-10-06 监控时 CH340、ST-Link、ODrive 曾随同一 USB Hub 一起重新枚举；应检查扩展坞、上行线和供电稳定性，避免将主机 USB 瞬断误判为控制器停机。
